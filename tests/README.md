# Logger V5 测试

在项目目录执行：

```bash
python3 tests/run_tests.py
```

只运行一项，例如归档顺序：

```bash
python3 tests/run_tests.py --case order
```

需要 `g++` 和 Python 3，不需要第三方 Python 包。脚本自行编译测试入口，
不改动项目 CMake、日志库实现或原来的 `main.cpp`。

## 两个程序的分工

- `rotation_driver.cpp`：根据命令行场景配置 Logger，提交消息，检查队列丢弃数。
- `run_tests.py`：准备已有文件，启动测试进程，等待它退出，再检查文件和输出。

必须等整个 C++ 进程退出：`log()` 返回、生产线程 `join()` 都不能证明后台
线程已经完成写入。当前 Logger 在静态单例析构时排空队列，测试利用这个行为。

每次测试在系统临时目录创建一个唯一的 `logger-v5-tests-*` 目录，每项测试
使用自己的子目录。日志和 `stdout.txt`、`stderr.txt` 会保留，方便人工核对；
项目中原来的日志文件不受影响。脚本退出码为 0 表示全部通过，1 表示有失败。

## 测试场景

| 名称 | 准备与操作 | 检查目标 |
|---|---|---|
| `normal` | 100 条编号消息，阈值 1024 字节，保留 3 个归档 | 文件大小、保留数量、最新消息及保留部分的连续顺序 |
| `no_loss` | 保留空间足够容纳全部 100 条消息 | 跨文件完整、有序、不重复，以及退出时排空队列 |
| `order` | 提前放入超限当前文件和三个带标记的归档 | 最旧归档淘汰、倒序移动、当前文件归档、新日志进入新文件 |
| `one_backup` | 保留数量设为 1 | 循环下边界及原有 `.1` 的淘汰 |
| `long_record` | 空文件先写入超过阈值的完整日志，再写一条短日志 | 允许完整超长日志，下一条触发滚动，不产生空归档 |
| `restart_append` | 同一目录运行两次，文件没有达到阈值 | 重启追加时保留原内容 |
| `restart_full` | 第一次退出后，把文件补到恰好 1024 字节，再启动 | 初始化读取已有大小，达到阈值后先滚动再写入 |
| `fallback` | 把 `.3` 准备成非空目录，使删除必然失败 | 只报告一次故障，当前及后续完整日志进入标准错误流，停止文件操作 |
| `concurrent` | 四个生产线程共提交 160 条消息 | 滚动期间不丢失、不重复，保持各生产者自身的顺序 |

有限保留策略会主动删除最早的日志，`normal` 因此只要求保留部分连续且以最后
一条消息结束。`no_loss` 则扩大保留数量，检查全部消息。两项测试的预期不同。

多线程调度没有固定全局顺序，`concurrent` 检查全体编号各出现一次，再单独检查
每个生产者内部的顺序，不要求全局编号递增。

这些测试覆盖文件滚动和删除失败后的替代输出。写入、刷新、关闭和重新打开的
其他故障路径没有逐一注入，标准错误流本身也不保证消息持久保存。
